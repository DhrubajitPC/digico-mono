## Rulings

- **Ruling 1 (pre-flight, Task 4):** Plan's `useOrders` passes `status: activeTab` (state typed `string`) and `origin: originFilter || undefined` into `trpc.orders.list.useQuery`, whose input type is `{status?: "all"|OrderStatusType, origin?: OrderOriginType, search?: string}`. tRPC's generated `useQuery` constrains `TInput extends RouterInputs[TPath]` → `string` is not assignable → this WILL fail `vp check` under the strict mode T1 enables. Fix: narrow the two state types at the hook boundary (`useState<"all" | Order["status"]>("all")` and `OrderOriginType | ""` for origin) — zero behavior change, consumers keep their literal setters. Cost if wrong: a cosmetic divergence from the plan's verbatim code.
- **Ruling 2 (pre-flight, note only):** `orders.create` inferred output type will be `Order | null` (db returns null-able) though the plan's interface says `→ Order`. Behavior-preserving (old REST route had the same surface; client never uses the create result value). No action.
- **Ruling 3 (pre-flight, note only):** T1 Step 4 says "copy of packages/utils/vite.config.ts" but the literal block omits `pack: {dts: {}}` — the literal block wins (no dts packaging needed for a source-consumed package).
